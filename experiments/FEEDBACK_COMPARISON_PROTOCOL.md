# 论文三：只改变反馈信息的对照

状态：准备材料，NOT_RUN。研究对象为对接技能迭代；不重复论文一的故障恢复结果。

两组保持相同 STM32 安全约束、对接任务与初态、传感输入、可编辑技能范围、Agent 模型和预算、最终评价规则。唯一实验因素是 Agent 能否看到结构化安全触发反馈；无反馈组仍受到相同安全限制。

反馈内容：关联的命令、规则 ID、触发原因、拒绝/限幅/停止决定、请求值与接受值、状态转换、时钟域及记录丢失情况。停止请求、通信发送、驱动确认、物理停稳必须分开。

评价任务成功、触发类型和频次、迭代次数/时间/成本、命令与实际响应差异及不安全转换。不能把必要保护触发减少当成单独成功；成功必须同时满足相同安全边界和任务标准。

首周只做 schema 和合成事件验证。日志接入只能发生在明确获批的独立开发分支，真实 HIL/对接需要额外现场授权。记录器必须有界，队列满时不能阻塞安全动作；测试丢失、重启、计数器回绕和额外时延。

统一 trace 和 harness 由 amr-faultbench 提供，并锁定具体提交。未知的命令关联、时钟精度和实际安全规则映射不能伪装成已接通。当前无固件改动、无两组对比结果。
